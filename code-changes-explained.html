Theme 1

PrimeNG was removed and replaced with native HTML plus Tailwind.

PrimeNG is a third-party Angular UI component library. It provides ready-made components such as cards and buttons, similar to using a backend starter dependency that gives you common behavior out of the box. In this change set, the app stops depending on PrimeNG for visual structure and styles each section directly.

What changed

The primeng and @primeuix/themes packages were removed, along with the app-level PrimeNG provider and custom preset file.

Why it changed

Removing the library reduces dependency lock-in and gives the app full control over layout, colors, dark mode, hover states, and responsive behavior.

What replaced it

Components now use ordinary HTML elements such as <div>, <a>, and <button>, styled with Tailwind classes.

Theme 2

Tailwind CSS became the primary styling mechanism.

Tailwind CSS is a utility-first CSS framework. Instead of writing separate CSS stylesheets with custom class names and style definitions (like a traditional stylesheet file), you write predefined utility classes directly in the HTML tags.

What changed

App-wide styling was consolidated into src/tailwind.css using Tailwind's @import, theme tokens (under @theme), and custom base layers. Traditional CSS styles inside src/styles.scss were reduced to third-party imports (like FontAwesome).

Why it changed

Consolidating styles in utility classes ensures visual consistency (by referencing standard values for margins, colors, etc.) and allows for rapid UI development without creating hundreds of lines of single-use custom CSS rules.

Backend Analogy

Think of custom CSS as writing raw SQL queries manually for every query. Tailwind CSS is like using Spring Boot annotations or custom properties — it's declarative, unified, and references central configuration variables.

Theme 3

A unified theme service adds full dark mode support.

The application now has a toggle that lets users choose between light and dark themes. The system also automatically checks the user's OS preference if they haven't manually chosen a theme yet, and remembers their choice for future visits.

How it works: State

An Angular service, ThemeService, manages the active state. This is similar to a singleton Configuration Bean in Spring Boot that reads initial config properties and provides live status updates.

Reactive Updates

The service uses Angular Signals (e.g. isDarkMode = signal<boolean>(false)). Think of a signal as a reactive Event publisher. When the theme state changes, UI listeners are instantly notified.

The CSS Trigger

Tailwind triggers dark mode styles using the class prefix dark: (like dark:bg-slate-900). These styles apply to an element only when the ancestor <html> element has the class .dark.

The Dark Mode Toggle Flow

[User Clicks Sun/Moon Button] │ ▼ (click)="toggleDarkMode()" on NavBarComponent │ ▼ Calls ThemeService.toggleTheme() │ ▼ Updates isDarkMode Signal & writes to LocalStorage (Cache) │ ▼ Adds/Removes '.dark' class on Document Root (<html> element) │ ▼ [CSS Layer Reacts] -> Tailwind dark: classes activate automatically

Theme 4

A complete visual and design overhaul modernizes the UI.

The entire portfolio has been redesigned using premium, modern UI visual trends. This replaces standard tables and generic cards with layout hierarchies, gradients, subtle micro-animations, and structured data blocks.

Core Visual Patterns Introduced

  • Glassmorphism (Frosted Glass panels): Creates container backgrounds using bg-white/80 dark:bg-gray-900/80 backdrop-blur-md. This overlays elements onto background gradients, maintaining high legibility while looking sleek and layered.
  • Gradient text headers: Used on main titles like "Dilanka Rathnasiri". The combination of bg-clip-text text-transparent bg-gradient-to-r from-primary to-secondary clips a left-to-right color gradient directly onto the text outlines.
  • Micro-interaction hover effects: Cards respond to user mouse hover dynamically using hover:shadow-2xl hover:-translate-y-2 transition-all duration-300. This promotes the card visually along the Z-axis by adding depth and translation.
  • Group Hover: By marking a container card with the group class, child elements inside it can react when any part of that card is hovered (e.g. group-hover:scale-110 to zoom an icon when hovering the card).
  • Timeline layouts: The Experience and Education items are rendered on a clean vertical timeline. The layout places a vertical boundary border border-l-2 relative, and aligns absolute-positioned circular dots (absolute -left-[9px] top-1.5 w-4 h-4 rounded-full bg-primary) directly over it.

Theme 5

Layouts and spacing adapt to any screen size.

The application has transitioned to a fully responsive, mobile-first design. Spacing, text sizing, navigation controls, and grids dynamically adapt to screen sizes from small phones to large desktop displays.

Mobile-First Approach

Standard styles (like p-4 or text-lg) apply to mobile screens by default. Breakpoint prefixes like md: and lg: are added to override defaults only for screens at or above those sizes.

Responsive Grids

Cards are organized using fluid CSS Grid classes: grid-cols-1 md:grid-cols-2 lg:grid-cols-3. This displays one column on mobile, two columns on tablets, and three columns on wide screens.

Hamburger Overlay

The navigation menu collapses into a drawer on mobile screens. Angular control flow selectively loads the drawer, and Tailwind classes hide or show desktop menu items based on current screen size.

Theme 6

Code cleaning, refactoring, and type safety improvements.

Unused metadata configurations, redundant files, and dead class declarations were removed. In addition, weak variable definitions (the equivalent of raw types or Object arrays in Java) were tightened into strong TypeScript interfaces.

Unused Imports & Metadata

Removed unused imports (like NgOptimizedImage in areas where it was no longer rendered) and stripped empty component metadata arrays (like imports: []) to clean up dependency trees.

Dead Code & Files

Unused variables (like title in AppComponent) and classes that no longer support components (like the PrimeNG custom-preset.ts) were deleted to reduce clutter.

Strict Type Definitions

Replaced loose, generic any[] types (similar to Java's raw List) with specific types (like WhatIDoItem[]). This enables compiling-time checks, IDE autocomplete, and prevents runtime field reference failures.

Glossary

Quick reference for frontend terms.

Here is a breakdown of the Angular and Tailwind terms used in this walkthrough, mapped to familiar backend concepts where possible.

Angular Core Terms

  • @Component: A decorator that defines an interface component (class + HTML template + styles). Equivalent to a view controller.
  • @Injectable: A decorator declaring that a class is a service managed by Angular's dependency injection container (similar to Spring's @Service or @Component).
  • signal: A reactive wrapper containing a value that alerts the DOM template to re-render automatically when updated.
  • inject(): Modern method to perform constructor-less dependency injection (similar to @Autowired in Spring).
  • OnInit / OnDestroy: Lifecycle hooks that run when a component is initialized or destroyed (similar to @PostConstruct and @PreDestroy).
  • @for ... track / @if: Modern Angular template controls to render loops and conditional blocks.
  • [class] / (click): Attribute bindings. [class] dynamically binds a CSS property; (click) registers an event listener callback.

Tailwind Core Terms

  • dark:: Breakpoint modifier that applies the class only when the document root has the .dark class enabled.
  • md: / lg:: Breakpoint modifiers that apply classes at or above specific screen widths (768px and 1024px respectively) for responsive design.
  • hover:: State modifier that applies CSS overrides when the user hovers their mouse pointer over an element.
  • group / group-hover:: Allows styling child elements based on the hover state of a parent element flagged with group.
  • transition-all: Instructs the browser to smoothly animate property shifts (e.g. translation, scale, shadow changes).
  • @layer: Groups styles into buckets (like base) to manage specificity rules and compile ordering.
  • @theme: Directive to configure global style tokens (like primary/secondary colors) at compile time.
